# TokenFleet beta.17 升级说明

使用 Codex 的 Mac 和 Windows 用户请在原电脑原位升级一次。源码版不会自动升级电脑；升级完成后，客户端会自动重算原统计窗口内可核实的历史，在下一次正常同步时覆盖原来的错误汇总和对应估算费用。服务端及网页不需要配套部署。

## 修复内容

- Codex 续写、回退后会为同一会话生成新的日志分段。Mac 现在按官方 `history_base` 指定的物理日志、字节与序号边界取得原累计值，只计新增部分，不把历史累计值记到续写当天。
- Windows 不再只选同一会话记录最多的一个文件，会保留不同物理分段，避免漏掉后续消耗；同一物理日志的副本仍去重。
- 回退前已经发生的请求仍然属于真实用量。不会因为回退聊天而删除已发生的消耗，也不会将两个不同分支恰好相同的累计值误当成同一请求。
- 被当前会话引用的压缩前序日志及其完整真实消耗也会一并核实，Mac 自带读取组件，Windows 沿用现有依赖，无需额外安装解压工具。
- Mac 的派生缓存自动重建；原始日志不改动。受影响的日期与型号重新汇总后通过原连接自动同步；若一项历史记录全部是重复量，会上传明确的零值纠正，避免旧错账残留。
- 原统计窗口、设备身份、昵称、签名、连接及换机后的上传日期限制保留。换机限制以前的日期不会因本次修复重新上传。服务器原有留存范围继续生效。
- 缺少前序日志、引用边界不一致、引用循环或超过安全读取上限时，本轮 Codex 汇总保留为不完整并停止上传，不用猜测的数字覆盖旧账。这样可以避免跨日的缺失片段被其他不完整小计覆盖。保留原始日志后联系管理员核对；这类记录不能保证自动修复。
- Mac collector：`0.2.6`；Windows collector：`0.2.0-windows.7`。

## Mac 原位升级

先退出 TokenFleet，保留原源码目录、昵称、状态、凭据与日志。进入原源码目录，用正式 Release 公布的完整 commit SHA 替换下面占位符，每一步成功并核对后再继续：

```bash
git fetch --no-tags origin refs/tags/v0.1.0-beta.17
git rev-parse "FETCH_HEAD^{commit}"
# 核对与正式 Release 的完整 SHA 相同
git checkout --detach <reviewed-commit-sha>
test "$(git rev-parse HEAD)" = "<reviewed-commit-sha>"
bash script/install_from_source.sh --enable-community-sync --community-server <原社群HTTPS地址>
```

纯本地用户沿用本地安装方式。无交互终端可加 `--yes`；系统钥匙串弹窗仍由本人授权，沿用原机器签名身份。不要卸载、清数据、复制其他机器的 App 或连接文件，也不要创建新昵称。

## Windows 原位升级

在原源码目录获取并核对上述 tag 与 Release 的完整 commit SHA，再检出该提交。按原安装方式重跑源码安装器，社群地址沿用原值：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\clients\windows\install.ps1 -CommunityServer <原社群HTTPS地址>
```

安装器保留原设备连接并更新已有同步任务。下一次正常同步会重新上传原范围内的正确日汇总；没有连接社群或未启用自动同步时，不会凭空建立新连接或新任务。无需重新领码、登记或修改昵称。

## 升级后验证

1. 确认版本为 beta.17，原昵称和社群连接仍在。
2. 等首次重算与同步完成，核对本机受影响日期和网页；网页汇总全部设备，本机只统计当前设备。下降表示纠正重复量，Windows 也可能因补回遗漏的续写而上升。
3. 再次刷新、重启后，没有新增请求时结果应保持不变；继续使用 Codex 后只增加新请求用量。
4. 反馈只提供版本、日期范围、来源状态和脱敏计数，不发送凭据、设备码、对话正文或完整日志。

首次重算可能比平时慢。保留原始日志和状态；修复失败先核原因，不降回有计数问题的旧版，否则旧版的新快照可能再次覆盖已纠正账本。需要回退时由管理员核对并安排同步边界。
