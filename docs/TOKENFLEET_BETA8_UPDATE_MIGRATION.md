# TokenFleet beta.8 更新与迁移状态

状态：beta.8 的 Swift、Web 与本机数据兼容性已完成当前范围的实现和验证；**生产发布、合并、部署均未获授权**。在可信签名和更新基础设施补齐前，不得宣传自动升级或稳定签名社群版。

## 已落地的 beta.8 能力

- Swift 已落地单屏入口、今日页、历史四层（总览 / 按工具 / 按模型 / 每日明细）、App 内社群 Top 10、排名海报和四段设置。
- Web 已落地动态工具/模型筛选、主力工具优先展示、安装与参与页、二维码说明文案，以及真实 1200 × 1600 排名海报。
- 社群边界已测试：100 / 200 成员、单批最多 50 个成员；多设备 1 / 2 / 4、同机重登轮换、停用和历史保留均已验证。

## 已完成的本机 beta.7 → beta.8 临时原地迁移测试

测试在本机临时副本中进行，并非对外发布或永久升级：

1. 先备份原 beta.7 App 和 `~/Library/Application Support/TokenFleet`。
2. beta.8 原地读取并保留了 120 日历史、设置和社群状态。
3. 测试后，以哈希核验将原 beta.7 App 与原 App Support 原样恢复，并重新运行原 beta.7。
4. 迁移后的测试副本保留在 `/private/tmp`，不作为生产或发布产物。

这证明当前数据结构可被 beta.8 读取和保留；它**不**证明 beta.7 用户能自动、安全地升级到一个稳定签名的社群版。

## 仍然阻断稳定升级的外部条件

- 没有可信的 Apple Developer Team ID、Developer ID 签名或公证凭据。
- 没有受控的 HTTPS 更新源，因此无法安全提供更新清单和安装包。
- 原本机 Keychain 继承已不可用，不能完成稳定签名社群版的永久升级验证。
- 若既有成员继承失败，只能为该既有成员安全补发设备码；不得借此新建成员，也不得占用或突破邀请批次边界。

因此 beta.8 当前只可表述为已实现并完成本机兼容性验证的构建；不能表述为可自动推送、可稳定签名升级，或已经发布。

## 未来获授权后的迁移原则（不构成执行授权）

1. 先取得可信 Team ID、Developer ID、公证能力和独立 HTTPS 更新端点。
2. 用签名且公证的 universal 安装包，在隔离设备复测 beta.7 覆盖安装、数据保留和 Keychain 继承。
3. 若 Keychain 继承失败，仅向已存在且未绑定的成员补发设备码；不创建新成员。
4. 发布前单独确认更新源、成员通知、回滚和生产影响；没有该授权不得部署、合并或发布。

## 回滚与数据边界

- 当前本机迁移测试已经恢复原 beta.7 App 与 App Support，恢复结果由哈希核验。
- 将来任何升级或回滚都不得删除本地历史、设置或社群数据，也不得操作未授权的服务或网站。
- 生产更新源、签名包、成员通知与实际发布均为后续独立授权事项。
