# 首批 50 人工具覆盖反馈

这份流程用于回答一个具体问题：成员确实在使用哪些 AI 工具，其中哪些已经被
TokenFleet 正确识别。它不新增后台遥测，也不要求成员提交任何对话内容。

## 发放节奏

1. 直接向首批 50 位成员发放同一个受限批次链接。
2. 成员安装并连接后，至少正常使用一天，再填写一次 30 秒反馈。
3. 管理员把公开榜已经观察到的工具／模型，与成员主动反馈交叉核对。
4. 按“使用人数多但尚未识别”的人数排序，优先选择前 2～3 个采集器。
5. 每个候选工具只向 2～3 位明确同意的成员征集脱敏诊断样本；先作为实验采集器
   验证，再决定是否纳入正式统计。

## 30 秒反馈表

以下字段可以直接建成飞书表单、问卷或群接龙：

1. 你的 TokenFleet 公开昵称（用于排查时对应；不愿填写可留空）。
2. 你过去 24 小时实际使用过哪些工具？（可多选）
   - Codex
   - Claude Code
   - CC Switch
   - Cursor
   - Kimi Code
   - Gemini CLI
   - OpenCode
   - Cline
   - Roo Code
   - Kilo Code
   - DeepSeek 独立客户端／CLI
   - ZCode
   - Hermes Agent
   - WorkBuddy
   - 其他（只填写工具名称）
3. 上述工具是否在 TokenFleet 的“历史／工具”中出现？
   - 全部出现
   - 部分出现
   - 完全没有出现
4. 没有出现的是哪些工具？
5. TokenFleet 显示的模型名是否符合你的实际使用？
   - 符合
   - 部分缺失
   - 完全没有显示
6. 如有缺失，只填写工具名和模型名；不要粘贴提示词、回复、代码、文件路径或
   完整日志。
7. 是否愿意在需要时提供一次脱敏诊断？
   - 愿意
   - 暂不

## 管理员统计口径

每个工具只记录四个数字：

| 工具 | 实际使用人数 | 已正确识别 | 部分识别 | 未识别 |
| --- | ---: | ---: | ---: | ---: |
| 示例：Cursor | 12 | 0 | 2 | 10 |

采集器优先级按“未识别人数”排序，而不是按群内提及次数或模型热度排序。同一工具
至少取得 2～3 台真实机器的一致证据，才从候选进入实验支持。

## 可直接发送给成员的说明

> TokenFleet 只在本机以只读方式处理支持工具日志，提示词、回复和代码不会进入统计或
> 文件。请正常使用一天后，用 30 秒告诉我们：你用了哪些 AI 工具、TokenFleet 有没有
> 显示出来。这个反馈只用于决定下一批优先支持哪 2～3 个工具；不要上传对话截图、
> 完整日志、数据库、密钥或文件路径。

## 诊断红线

- 不要求成员上传完整本地数据库、会话文件、聊天截图或终端历史。
- 不根据对话文字、文件大小或运行时长估算 Token。
- 只核对工具版本、采集器状态、数据表／事件结构，以及明确存在的 Token 用量字段。
- 诊断样本必须先去除用户名、家目录、项目路径、提示词、回复、代码、密钥和会话 ID。
- 没有稳定本地用量字段的工具保持“尚未支持”，不能用推算数字进入排行榜。
