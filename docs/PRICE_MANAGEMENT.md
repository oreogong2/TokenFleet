# Unified public price catalog and weekly maintenance

The server publishes only public prices with verified official-source provenance at `GET /api/v1/public/price-catalog`. Signed devices use `GET /api/v1/device/price-catalog` for their own organization. Schema and normalization versions and a monotonic catalog revision are explicit; the content hash and ETag change when the public catalog changes. Private prices, owner/organization identifiers and legacy prices without source evidence are excluded.

An organization administrator issues a dedicated credential with `POST /api/v1/price-management/credentials` and can revoke it by ID. The response has `Cache-Control: no-store`; save its raw credential directly to a local file outside Git with mode 0600, never to chat, logs, command arguments or a public workflow. The database stores only its hash. It expires within 90 days and loses authority if revoked or its owner is disabled/demoted. Ordinary member/device/user/admin endpoints reject this credential.

The price-only workflow can read missing-price aggregates and import a new immutable, public price version from an allowlisted official price page. It cannot select another organization, make a private price public, reprice already-priced rows, change usage labels/tokens/identities, delete data or create more credentials. Source page, verification date and effective-date basis are recorded. Unknown providers require a verified official-domain addition; no generic rate is substituted.

Supply `effective_basis=official_date` and the date explicitly published by the provider. When a current-price page has no effective date, supply `effective_basis=ledger_first_seen` without a date: the server resolves the model's first retained-ledger appearance across proven aliases. Missing first appearance is rejected rather than invented.

Imports atomically backfill only that model's originally unpriced, non-deleted exact rows inside retention. Any existing price reference or amount/currency stays unchanged, including private rates. The response reports before/after coverage and currency amounts without member/device identifiers. Repeating an identical import is safe; a conflicting immutable version is rejected. A verified current catalog supersedes unverified legacy public rates for new pricing, while existing frozen costs remain until the separate authorized historical correction.

`script/price_maintenance.py` reads only a dedicated credential file, requires HTTPS, refuses redirects and calls only these price APIs. `inventory --output <private-file>` saves aggregates privately; `import --prices-file <official-json> --receipt <private-file>` previews by default and requires `--apply` to write. It does not research or invent rates, connect to ECS/SQL, clean unknown data or invoke the broad historical repricing endpoint. API errors report status/category only.

Weekly workflow: fetch inventory, check official public pages, prepare evidence-backed prices, import through the dedicated API and report new versions plus missing-only backfill results. Mark genuinely unavailable public prices as “无公开价”; distinguish insufficient pricing conditions from absence of a public price. Keep credentials, inventories, receipts and member information outside Git. Stay quiet if there is no meaningful change; report a new price, failure or required action. Enable scheduling only after the new server API is approved and deployed.

The first comprehensive historical repricing remains a separate administrator-only preview/apply operation after backup and isolated restore validation. Weekly maintenance never opts into that mode. Production imports, broad historical correction and ranking activation require the corresponding approved deployment and scope; local tests are not production receipts.
