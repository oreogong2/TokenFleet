# Unified public price catalog and weekly maintenance

The server publishes only public prices with verified official-source provenance at `GET /api/v1/public/price-catalog`. Signed devices use `GET /api/v1/device/price-catalog` for their own organization. Schema and normalization versions and a monotonic catalog revision are explicit; the content hash and ETag change when the public catalog changes. Private prices, owner/organization identifiers and legacy prices without source evidence are excluded; the verified 2026-08-14 catalog is retained as history.

An organization administrator issues a dedicated credential with `POST /api/v1/price-management/credentials` and can revoke it by ID. The response has `Cache-Control: no-store`; save its raw credential directly to a local file outside Git with mode 0600, never to chat, logs, command arguments or a public workflow. The database stores only its hash. It expires within 90 days and loses authority if revoked or its owner is disabled/demoted. Ordinary member/device/user/admin endpoints reject this credential.

The price-only workflow can read missing-price aggregates and import a new immutable, public price version from an allowlisted official price page. It cannot select another organization, make a private price public, reprice already-priced rows, change usage labels/tokens/identities, delete data or create more credentials. Source page, verification date and effective-date basis are recorded. Unknown providers require a verified official-domain addition; no generic rate is substituted.

Historical rates verified against official pages on 2026-08-14 remain dated price versions, with evidence retained in `docs/TOKENFLEET_BETA8_PRICING.md`. They are not treated as unverified guesses. An administrator can import them with `effective_basis=historical_verified`, an explicit retained historical date and a bounded `pricing_note`; the price-only credential cannot certify history. Existing historical records and their rates/dates are not deleted or overwritten.

For the initial catalog, use a proven provider effective date (`official_date`). GPT-5.6 Sol and its documented GPT-5.6 alias retain the original rate before 2026-08-21; the [official API changelog](https://developers.openai.com/api/docs/changelog) establishes the promotion start on that date. Where no earlier verified price exists and a current-only official page gives no date, `ledger_first_seen` resolves the model's first retained appearance. It cannot replace an existing verified history.

Future observed price changes use `first_observed`, with `effective_from` equal to `source_checked_at`: the new price starts on the observation day and earlier dates retain their version. Price-only credentials enforce this basis when a model already has a verified version. Verification dates are validated against the organization's timezone. Repeating an identical import remains safe.

Imports atomically backfill only that model's originally unpriced, non-deleted exact rows inside retention. Any existing price reference or amount/currency stays unchanged, including private rates. The response reports before/after coverage and currency amounts without member/device identifiers. Repeating an identical import is safe; known rates, scope and provenance are immutable. For Claude write counters without a 5-minute/1-hour breakdown, use the official 1-hour write rate as an estimate and retain the note “缓存写入按 1 小时档估算” in each applicable version. This does not claim measured TTL or change any token counters. TTL collection is deferred. Other providers receive no automatic TTL assumption. Explicit null cache rates mean the official page or available usage breakdown does not determine that component. They are published as null and displayed as “未确定”, never as a free rate. A zero counter does not need that component rate; any nonzero unknown component keeps the entire bucket unpriced. Completing a previously unknown rate from the same official source increments the catalog revision and backfills only previously unpriced exact rows; already-priced rows stay frozen. Changing a known rate or reverting it to unknown is rejected. Once an organization has a verified current catalog, new public estimates use only that catalog; an unlisted model cannot fall back to an unverified legacy rate. Existing frozen costs remain until the separate authorized historical correction, which also clears unsupported legacy public estimates without deleting usage or changing labels. Private rates remain outside that correction.

`script/price_maintenance.py` reads only a dedicated credential file, requires HTTPS, refuses redirects and calls only these price APIs. `inventory --output <private-file>` saves aggregates privately; `import --prices-file <official-json> --receipt <private-file>` previews by default and requires `--apply` to write. It does not research or invent rates, connect to ECS/SQL, clean unknown data or invoke the broad historical repricing endpoint. API errors report status/category only.

Weekly workflow: fetch inventory, check official public pages, prepare evidence-backed prices, import through the dedicated API and report new versions plus missing-only backfill results. Mark genuinely unavailable public prices as “无公开价”; distinguish insufficient pricing conditions from absence of a public price. Keep credentials, inventories, receipts and member information outside Git. Stay quiet if there is no meaningful change; report a new price, failure or required action. Enable scheduling only after the new server API is approved, deployed and successfully read back through its real management interface. Remain paused until then.

The first comprehensive historical repricing remains a separate administrator-only preview/apply operation after backup and isolated restore validation. Its preview includes amounts and coverage before/after. When an old public cost relied on a guessed cache rate and the verified rate is unknown, that explicit full correction clears the old price/amount/currency together; weekly imports never clear or alter already-priced rows. Weekly maintenance never opts into that mode. Production imports, broad historical correction and ranking activation require the corresponding approved deployment and scope; local tests are not production receipts.

The Mac client fetches this public catalog before a normal usage refresh and keeps an origin-bound atomic cache for offline use. Invalid, unsupported or older catalogs do not replace the last valid copy. Without a catalog there is no built-in or generic price fallback. Raw log costs remain in the collection cache, while displayed estimates price the same complete daily tool/model buckets and micro-unit HALF_UP rounding as the server. A catalog change bypasses the unchanged-source checkpoint and re-estimates local amounts without changing Token counters, model keys, source keys or dates.
