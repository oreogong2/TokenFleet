# TokenFleet 产品规格（工作名）

状态：社群首版开发基线

日期：2026-08-09

代码基线：TokenStep `v0.1.48` / `ef13871`

## 1. 产品定义

TokenFleet 首版是一套面向邀请制社群的 AI Token 本地账本与排行榜：

- macOS 客户端保留 TokenStep 的所有个人统计能力；
- Windows 10/11 参赛端采集 Codex / Claude Code 本地 JSONL，以 DPAPI 保护设备
  凭据，通过计划任务自动同步并可打开公榜；首版不承诺与 macOS 相同的完整桌面明细；
- 社群管理员只需填写昵称创建参赛者，并私发短期、单次设备接入码；参赛者
  不需要注册网页账号，同一参赛者可以绑定多台设备；
- 服务端只为一个显式配置的社群生成只读公开榜投影，不开放匿名注册、
  自建圈子或跨社群发现；
- 现有成员默认不进入公开榜，只有管理员在获得本人同意后显式开启
  `public_profile_enabled` 才会展示；
- 官方客户端只向组织后台发送聚合用量字段和最小版本元数据；后台没有
  prompt、回复、代码、文件或项目路径的展示字段；
- 公开榜展示昵称、排名、聚合 Token、工具、模型、日趋势和按价格表计算的
  估算费用；不展示邮箱、内部用户/设备 ID、设备明细、IP、逐小时作息、
  会话数或消息数；
- 生财排行榜由成员自己的官方 OpenToken 独立连接，TokenFleet 不代理、不保存其个人上传地址或凭证。

工作名 TokenFleet 仅用于开发，正式发布前可统一换名。TokenStep 的 MIT 版权和许可声明必须保留。

## 2. 用户与权限

### 2.1 个人用户

- 在本机查看今日圆环、历史、统计、工具、模型、费用估算和额度。
- 展开某一天，分别查看每个工具及其模型的 Token 构成。
- 管理自己的设备、社群连接和同步状态。
- 参与社群榜后，公开昵称、汇总用量与估算费用；本地原始日志和内部身份不公开。

### 2.2 社群管理员

- 使用现有管理员账号登录后台；首版不开放社群自助创建。
- 新增邮箱/密码登录账号只允许管理员；既有 legacy member 仅向后兼容，不再新建。
- 只填昵称即可创建非登录参赛者，并为每台设备生成短期、单次接入码；可在
  误发时禁用参赛者阻止登记，未使用的码自动过期。
- 查看组织汇总、成员、设备、工具、模型与成本。
- 禁用丢失或离职设备；禁用后新上报必须立即失败。
- 配置组织时区、数据保留期和价格版本。
- 官方协议和管理员界面不提供 prompt、回复、代码、文件、项目或会话正文的字段与视图。
- 在获得成员同意后开启或关闭其公开榜资格；关闭只撤下公开投影，不删除私有历史账本。

### 2.3 社群参赛者

- 不创建邮箱、密码、微信或会员账号，也不登录管理后台。
- 收到管理员私发的专属链接后，先查看上传与公开字段，再在客户端手动粘贴
  一次性接入码并确认；网页不得自动连接客户端或读取剪贴板。
- 一台设备消费一个接入码；新增 Mac 或 Windows 设备由管理员为同一参赛者再生成一个接入码。
- 可在本地客户端查看个人统计，并通过公开榜查看自己与其他已公开参赛者的
  聚合结果；不能查看设备明细或组织管理配置。

### 2.4 公开访客

- 无需登录即可查看唯一社群的公开排行榜和已公开成员主页；
- 可按工具、模型、时间范围以及含缓存、非缓存、估算费用口径筛选；
- 只能读取公开聚合字段，不能枚举组织、邮箱、内部用户、设备或私有价格配置；
- 首版不提供关注、动态、私信、PK、城市榜或用户自建圈子。

### 2.5 接入链接

- 接入链接采用规范 HTTPS 的 `/join#code=<one-time-code>`（或等价 fragment）形式；
  fragment 不发送给 Web 服务器，也不得进入服务端访问日志、Referer、分析事件
  或错误上报。
- 页面可以在内存中读取并显示接入码，但不得写入 Cookie、localStorage、
  sessionStorage、IndexedDB、截图或日志；离开页面时清除内存值。
- 首版不使用携带凭据的自定义 URL Scheme，不自动读取剪贴板，也不把接入码
  自动传给桌面客户端。成员需主动复制，在客户端 `SecureField` 中粘贴并确认。
- 正式构建固定唯一 canonical HTTPS 社群服务 origin，成员不能输入或覆盖服务器
  地址；只有测试/开发构建可以显式 override，且不得进入正式签名包。
- 连接确认前必须说明：客户端会立即上报当前仍可验证的历史日聚合，并在之后
  持续后台同步；不能用模糊的“连接”文案代替上传范围与公开字段告知。
- 接入码必须短期、单次、绑定一个参赛者；服务端数据库只保存哈希。成功登记
  后改用每台设备独立凭据，接入码立即失效。社群一键接入流程默认有效 60 分钟、
  最长 24 小时。

## 3. TokenStep 能力对齐

本节能力对齐适用于 macOS 原生客户端。Windows 首版只覆盖 Codex / Claude Code
采集、DPAPI 安全连接、手动与计划任务同步、状态/预览命令和打开公榜，不宣称具备
本节全部原生桌面能力。

以下能力是回归基线，团队功能不得造成退化：

1. 菜单栏实时展示今日 Token 与目标圆环。
2. 轻量浮层、原生主窗口与 Token Island。
3. 今日、历史、统计、模型、工具和隐私页面。
4. 多圈每日目标与可配置目标值。
5. 最近 30 天趋势和近 8 个月活动墙。
6. Codex 本地 JSONL 增量采集与 SQLite 回退。
7. Claude Code 本地 JSONL usage 采集与去重。
8. CC Switch 代理日志实验采集与跨来源去重。
9. 工具、模型、Token 四类原子计数和费用估算。
10. 打开面板刷新、接电/电池/低电量节能刷新策略。
11. 开机启动。
12. 主题、语言和显示设置。
13. 页面截图、每日分享卡、昨日节奏分享卡。
14. Codex / Claude Code 剩余额度（默认关闭）。
15. 自动检查更新与签名 DMG 下载流程。
16. 本地数据与隐私说明。
17. Agent 活跃、节奏和现有排行榜展示能力。

新增能力：

- 历史按日展开到工具、模型及 input/output/cache read/cache write；
- 旧数据兼容：只有边际汇总时明确标注，禁止伪造工具×模型交叉值；
- 可选团队同步、手动同步、后台同步、离线重试和最后成功状态；
- 复用多组织隔离能力的单社群、多参赛者、多设备中心账本；
- 团队 Web 仪表盘、RBAC、价格版本、数据保留和设备管理。
- 邀请制单一社群公开榜、公开个人页和本地浏览器生成的分享海报；
- 分享海报只使用公开投影，包含筛选口径、Top 10、本人位置和无凭证的公开链接。

## 4. 统计口径

### 4.1 原子字段

每个可上报桶只包含：

- `date`：设备本地日历日期，格式 `YYYY-MM-DD`；
- `timezone`：采集时 IANA 时区；
- `tool`：规范化客户端名称；
- `model`：采集到的原始或规范化模型名；
- `source`：采集来源，默认 `local`；
- `input_tokens`：不含缓存读写的输入；TokenStep 原始 `inputTokens` 已包含缓存，客户端必须先扣除 `cache_read + cache_write`；
- `output_tokens`；
- `cache_read_tokens`；
- `cache_write_tokens`；
- `collector_version`；
- `schema_version`；
- `completeness`：`exact`、`legacy_marginal` 或 `fallback_estimate`；
- `deleted`：服务端向后兼容的可选字段，默认 `false`；`true` 时四类 Token 必须全为 `0`。macOS 客户端 v1 不自动发送删除。

派生值：

- `total_tokens = input + output + cache_read + cache_write`；
- `norm_tokens = input + output`；
- `estimated_cost` 使用有版本号的价格快照计算。

只有四类原子字段守恒的 `exact` 桶参与价格估算。分项不完整的旧数据或 fallback 不得伪装为 exact，也不得按某一类 Token 估价；客户端可以保留本地总量，但团队同步应跳过无法诚实拆分的桶并报告遗漏数。

客户端 v1 不把“本轮缺失”解释为删除：即使同日另一工具/采集源仍有 exact 数据，也无法证明缺失来源健康完成了全量覆盖。普通同步与 force 都只上传当前可验证的 exact 桶，stale hash/早期预发布删除标记原样保留且不重传；key 重新出现时正常 upsert。未来若要自动删除，必须先增加可验证的权威覆盖证明。服务端继续保留 tombstone 协议和删除版本，防止受支持的删除被较旧离线数据复活。

同步成功响应必须满足 `created + updated + unchanged == buckets.count`，`ledger_version` 允许为任意非负值。桶全部在留存线外时，服务端可返回匹配的 `unchanged` 与 `ledger_version: 0`；客户端应视为成功而不是停止自动重试。

失败恢复必须区分错误类型：408/425/409/429/5xx 与网络错误按 transient 退避；普通 request-rejected 4xx 不自动无限重试，但用户修复后可用“立即同步”显式 force；401/403 凭据失效无论 force 与否都要求重新连接。

### 4.2 多设备

- 组织视图汇总成员的所有启用设备，不设 3 台上限。
- 设备由随机 UUID 标识，不使用主机名、序列号、MAC 地址或硬件指纹。
- 同一设备重跑同一桶时覆盖，不累加重复值。
- 不同设备即使内容相同也分别计入；跨设备是否代表真实重复调用无法由本地日志可靠判断，界面必须明确“设备用量合计”。
- 原始记录保留设备维度，组织汇总在查询时派生。

### 4.3 时间

- 服务端记录接收时间为 UTC。
- 每个 v1 日桶保留设备上报的 IANA 时区和本地日期。
- v1 查询按设备上报的本地日期筛选；组织时区只作为默认显示口径。若范围内出现多个设备时区，API 和界面必须明确提示，不能假装已无损重归日。
- 跨时区无损重组需要 UTC 小时桶，列入 v2 协议；不能从已经聚合的日桶反推。
- 上游 TokenStep 0.1.48 的现有账务日历硬编码为 `Asia/Shanghai`。为避免静默重切历史，本轮客户端继续原样上报该时区；“按系统时区记账”需要单独的版本化迁移，不能当作无行为变化的小修。

### 4.4 成本

后台分开显示：

- API 等价估算：根据 Token 与价格版本计算；
- 实际 API 费用：将来由账单导入，不能与估算混称；
- 固定订阅费用：按席位/套餐另记，不能由 Token 反推。

Token 用量不得作为个人绩效或产出指标。

进入公开榜的成员默认公开 API 等价估算费用。页面和海报必须同时标注币种、
时间范围及“按公开价格表估算，不等于真实账单”；匹配不到价格的明细显示
“未定价”，不得按零成本或模型家族兜底价展示。组织协议价、实际发票和固定
订阅费用不进入公开榜。为兼容既有私有价格，价格版本默认不具备公开估价资格；
管理员必须把用于 API 等价估算的版本显式标记为 `public_estimate`。公开投影只读取
该版本已冻结的费用，切换参赛者公开状态时不再提供单独隐藏费用的开关。

## 5. 隐私与安全边界

官方 TokenFleet 客户端只发送第 4 节定义的聚合字段；服务端上报 schema
不接收下列内容字段，并对未知字段和 Unicode 控制/格式字符严格拒绝：

- prompt、模型回复和对话正文；
- 代码、文件内容和项目名称；
- repo、路径、skill、MCP、agent 名称；
- 会话 ID、请求正文和 Claude/Codex 登录凭证；
- 生财 OpenToken 的专属 URL、token、device secret 或本地配置。

这个协议边界可以验证官方客户端 payload 和服务端 schema，但不能对恶意或
自行修改的已登记客户端做“绝不夹带敏感信息”的语义证明：攻击者仍可能把
内容编码进表面合法的 `tool/model/source`。因此设备登记、独立签名密钥、禁用、
日志脱敏和异常标签审查共同构成信任边界，文档不得把 schema 约束表述为对任意
客户端的绝对不采集保证。

必须实现：

- TLS 部署要求；
- 一次性设备邀请；
- 每台设备独立密钥；
- 请求 HMAC、时间窗、nonce 防重放；
- 注册 secret 只在注册时显示，服务端只保存派生 signing key；派生 key 本身仍是敏感凭证，数据库和备份必须加密并限制访问；
- 多租户查询强制带组织作用域；
- 管理员 RBAC；非登录参赛者没有 Web session。既有可登录 member 仅保留兼容，
  不作为社群首版接入流程；
- 设备吊销；
- 未知上报字段拒绝；
- 可配置保留期、导出与删除入口。

公开榜额外要求：

- `PUBLIC_ORG_SLUG`（或等价单一配置）默认为空；未显式配置时公开 API 关闭；
- 公开接口不接受任意组织参数，只能读取配置的唯一社群；
- 现有/新建成员的公开开关默认关闭，成员禁用或关闭公开后立即从公开榜和
  公开个人页消失，私有历史仍按保留策略保存；
- 稳定随机 `public_id` 与内部用户 ID 分离，公开响应不得返回内部 ID；
- 首版不采集、不保存、不筛选城市；
- 公开日趋势只按日聚合，不公开逐小时、会话、消息或设备节奏；
- 分享图在浏览器本地生成，二维码/链接必须是同源 HTTPS 公开页且不含 token、
  secret、email、内部 ID、userinfo 或认证 query。
- 非登录参赛者的 email 与 password 必须同时为空，禁止伪造占位邮箱或共享密码；
  管理员创建参赛者与一次性接入码应在同一事务完成，原始接入码只返回一次。
- `/join` 页面读取 fragment 后必须立即用 `history.replaceState` 清除地址栏和历史
  项中的码，并在 `pagehide` 清空内存；任何正式页面不得接受 query 中的接入码。

## 6. 生财排行榜边界

支持方式仅为：

```text
本地 AI 日志 ──> TokenFleet 客户端 ──> 社群服务端
      └────────> 官方 OpenToken ─────> 生财排行榜
```

- 两条链路分别认证、分别重试、分别记账。
- 社群服务故障不能影响生财上榜。
- 生财接口变化不能影响 TokenFleet 账本。
- TokenFleet 仅显示连接说明和状态提示，不接管或转发个人凭证。

## 7. 非目标（首个稳定版）

- Linux 原生采集端；
- 微信登录、自助注册、手机号/邮箱找回体系；
- 面向所有人的开放平台、用户自建圈子、多社区发现与付费；
- 城市采集、城市榜、关注、动态、私信与 PK；
- Kimi Code、Gemini CLI、OpenCode 等新增采集器（按社群真实需求另立版本）；
- prompt 或项目级生产力分析；
- 复制生财的品牌、视觉、会员关系或其反作弊逻辑；
- 通过用量评价员工绩效；
- 自动导入供应商发票；
- 跨设备会话级去重。

## 8. 发布门槛

“完成”定义为：

- 已知 P0/P1 缺陷为 0；
- TokenStep 原有自动化测试全部通过；
- 新增模型、迁移、签名、幂等、租户隔离、RBAC、多设备和成本测试通过；
- Web 关键路径在真实浏览器回归通过；
- 匿名公开 API 的字段白名单、单社群隔离、默认不公开、关闭后撤榜、未定价、
  极值、稳定排序和限流测试通过；
- 排行榜与公开个人页在桌面、平板、手机通过真实浏览器回归，分享 PNG 只包含
  公开字段且二维码/链接无凭证；
- macOS 客户端可重复构建，Windows 参赛端可在 Windows 10/11 完成安装、登记、
  手动同步、计划任务自动同步、打开公榜与卸载回归；
- 空数据、离线、401/403、超大数、旧数据和跨时区均有测试；
- 文档、部署、备份/恢复、升级与回滚步骤可执行；
- 仍需在真实团队做 5–10 人、14 天试运行后，才可称为生产稳定版。

任何软件都无法证明“绝对没有问题”。本项目以以上可验证门槛替代模糊承诺。
