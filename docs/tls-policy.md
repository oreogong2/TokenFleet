# Application certificate policy

At startup, before importing HTTP client modules, the application refreshes a private CA bundle from the Python build's original operating-system CA file and removes two distrusted root fingerprints. It sets SSL_CERT_FILE, SSL_CERT_DIR and REQUESTS_CA_BUNDLE; the CA directory remains empty. Certificate and hostname verification remain enabled. The fixed certifi version is pinned for clients that explicitly use its bundle.

Local processes default to a persistent directory at `$XDG_STATE_HOME/tokenfleet/tls-policy`, or `$HOME/.local/state/tokenfleet/tls-policy` if XDG_STATE_HOME is unset. Deployment may set TOKENFLEET_TLS_SOURCE and TOKENFLEET_TLS_OUTPUT to explicit local paths. Output must be absolute, belong to the effective user, and have no group/other write access. Missing parent directories are created privately. All ancestors must belong to that user or root and deny other writers; shared sticky directories such as /tmp are rejected. Root must not reuse another user's output. Invalid or unavailable input stops application startup. No platform trust store is modified.

The standard `deploy/tokenfleet.sh` entry point includes `deploy/compose.tls.yml`. It supplies a dedicated mode-0700 tmpfs at `/run/tokenfleet-tls`, owned by the container application user. This mount lasts for the full container lifetime, is outside shared /tmp, and supports the existing read-only root filesystem. When invoking Docker Compose directly, include both `-f deploy/compose.prod.yml -f deploy/compose.tls.yml`. Using only the base file with a read-only root filesystem will fail closed because it has no protected writable state directory.

This POSIX helper requires fcntl and directory file descriptors. The manifest detects accidental inconsistency; it does not authenticate files against an attacker with the same operating-system identity. Keep the output for the entire process lifetime, including later TLS requests. Do not add the persistent state directory to temporary-file cleanup jobs. The dedicated container tmpfs is cleared only when the container stops or is replaced. Each startup regenerates the bundle from the original source; bundle, manifest, lock and empty-directory permissions are checked.

The normal application startup path applies this policy after fresh builds and restarts. Standalone maintenance commands that do not import the application must use their own verified CA settings. Rollback uses the previous application image and retains its prior certificate behavior.
