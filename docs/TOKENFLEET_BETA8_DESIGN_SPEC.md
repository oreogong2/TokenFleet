# TokenFleet beta.8 桌面体验规格

状态：设计约束与 beta.7 功能保全边界已由维护者确认，进入实现。

## 1. 方向

beta.8 采用“熟悉但明显更像 TokenFleet”的中度改版，不做推倒重来的视觉换肤。

- 保留产品名 `TokenFleet`、口号“每天一个亿”、每日目标和今日／历史／社群三段导航。
- 保留明亮底色、绿色主色和现有用户已经熟悉的操作路径。
- 去掉最接近 TokenStep 的多圈健身皮肤；保留一个干净的 TokenFleet 目标圆环，继续表达“每天一个亿”、当前圈数和真实超额百分比。
- 菜单栏识别符号使用 16pt 原生单色进度圆环，交给 macOS 管理位置与拥挤，避免遮挡系统或其他应用状态图标。
- 舰队语义只用于少量文案与连接状态，不引入大面积深海、仪表盘或科幻装饰。

### 功能保全原则

beta.8 是品牌和信息层级重构，不是功能精简版。除明确不安全、不准确或带有旧品牌残留的能力外，beta.7 已经工作的用户能力必须保留：

- 今日客户端和今日模型分布。
- Agent 今日／近 7 日切换、按来源筛选、24 小时堆叠活动图、活跃小时、近 7 日均值和缓存命中率。
- Codex／Claude Code 的 5 小时与 7 天额度、重置倒计时和更新时间；只有真实读取到窗口时才显示。
- 近 7／30／90 天／全部统计、近 8 个月活动墙和逐日展开明细。
- 工具 → 模型 → 输入／输出／缓存读／缓存写的精确明细；旧数据继续明确标注分项不完整。
- 今日成绩、昨日成绩、昨日节奏三种分享，以及复制／下载／页面截图能力。
- 社群榜排名上下文、采集器状态、每日目标预设、刷新频率、多语言、开机启动、更新与隐私设置。

禁止为了视觉简化而把已有数据字段或入口静默删掉。

### 九套主题与工具识别色

- 用户主题扩展为 9 套：青绿、海蓝、信号青、靛蓝、紫藤、玫瑰、珊瑚、琥珀、石墨。
- 主题影响画布、按钮、目标刻度、活动墙和强调状态；每套都必须满足正文与状态信息的可读性。
- 工具识别色独立于主题保留，确保 Codex、Claude Code、Hermes、ZCode 和 CC Switch 在所有图表中颜色一致。
- 告警琥珀、错误红和成功绿是语义颜色，不随主题变成含义不明的装饰色。

## 2. 单屏入口

### 默认

- 常驻入口使用系统菜单栏右侧的紧凑单色 TokenFleet 进度圆环，不显示常驻 Token 数字。
- 不占用刘海左右的屏幕中段，不创建悬浮胶囊。
- 点击后打开统一的 TokenFleet 快览弹窗。

### 可选

- 菜单栏空间充足时，用户可开启“圆环＋今日 Token”；默认仍只显示紧凑圆环。
- beta.8 不提供刘海旁悬浮胶囊；旧设置中的自动／刘海左／刘海右值会统一迁移为原生菜单栏，不继续遮挡其他状态项。

### 找回入口

- 从应用程序或 Spotlight 再次打开 TokenFleet，必须显示主窗口。
- 不新增不存在的 Dock 开关；菜单栏拥挤时，从应用程序或 Spotlight 再次打开即可找回主窗口。

## 3. 快览弹窗

保留当前从上到下的信息顺序，但减少装饰并统一所有入口的动作能力。

1. TokenFleet 标识、名称、“每天一个亿”和同步状态。
2. 今日 Token 大数字。
3. 一个干净的目标圆环，显示当前数值、目标值、圈数和真实百分比；超过 100% 后继续按每 1 亿一圈表达，不叠加多圈健身皮肤。
4. Codex、Claude Code 和其他工具的流量占比条。
5. 一行相对节奏：与近 7 个日历日或近 7 个活跃日比较时必须明确口径；不足样本时不显示。
6. 真实读取到额度时显示紧凑额度摘要；无额度字段时不猜测。
7. 已连接社群时，显示全宽主按钮“社群排行”；未连接时显示“连接社群”。
8. 次级动作统一为“主窗口／刷新／设置／退出”。

菜单栏快览、主窗口与截图页必须复用同一动作模型，禁止再各写一套能力。

## 4. 主窗口

### 框架

- 保留左侧导航和“今日／历史／社群”三页。
- 保留设置入口、刷新状态、截图入口。
- 最小窗口需要覆盖小屏 Mac，不再要求内容区依赖 1080px 才能正常阅读。

### 今日

- 头部保留 `TokenFleet / 每天一个亿`。
- 原多圈健身皮肤改为单个干净目标圆环：今日 Token、每日目标、圈数和真实完成比例放在同一视线；旁边继续显示连续活跃、相对节奏与 API 标准价估算。
- 下方完整保留客户端、模型、Agent 工作和累计指标，但减少重复卡片边框。
- 相对节奏使用“比近 7 个活跃日高／低 x%”等事实文案；不足两个可比较活跃日时隐藏，不输出误导性百分比。
- 费用明确标注为估算；无法可靠定价时显示“暂未估算”。

### 历史

- 保留活动墙和逐日明细。
- 保留近 7／30／90 天／全部切换、按客户端与按模型汇总，以及工具到模型的逐层展开。
- 新增当前连续活跃天数，并解释计算口径。
- 费用列使用统一估算标签和精度。

### 社群

- 已连接时首要动作是“打开社群排行”，并展示同步状态、最近同步和本人连续活跃。
- 排名必须带上下文：`第 x / y 名`、参榜人数、超过参榜用户比例和榜单更新时间；不得只显示孤立名次。
- 未连接时首要动作是“连接社群”，不显示不可点击的排行按钮。
- 保留隐私边界，但删除生财、OpenToken 等无关用户叙事。

## 5. 设置

保持现有设置能力，按四组收口：

1. 显示：原生菜单栏紧凑圆环、可选今日 Token 数字、可再次打开的主窗口、9 套主题、语言。
2. 统计：每日目标、刷新、费用估算说明、采集来源。
3. 社群：连接状态、同步、社群排行、设备信息。
4. 系统：自动启动、可信更新、隐私、版本。

不再使用左右两列无限堆卡；窄窗口时改为单列。

## 6. 费用估算

- 产品文案统一使用“API 标准价估算”，不得称为真实账单、订阅成本或用户实际支出。
- 优先采用来源记录中的实际费用；其次才使用 TokenFleet 内置、带版本号和核验日期的公开 API 价格。
- 必须按模型精确匹配，并分别计算输入、输出、缓存读和缓存写；不得把未知模型按 `$1 / MTok` 等通用价格猜算。
- 模型别名只能映射到能被官方资料或来源字段证明的具体计价模型；无法证明时标记未定价。
- 只有分项完整的 Token 记录才能用分项价格估算。只有总量且无法证明输入／输出比例的记录标记未定价。
- 界面显示价格版本、核验日期、已定价 Token、未定价 Token 和覆盖率；部分覆盖时金额旁必须出现覆盖提示。
- 价格变化不得静默重算已冻结的服务端历史版本。桌面本地重建时也要记录当前价格版本，避免把估算冒充账单对账结果。

## 7. 分享图片

- 保留浅色和绿色品牌，不使用旧的多圈健身环与 `tokenstep.app`。
- 主视觉为今日 Token 数字和水平目标刻度。
- 保留今日成绩、昨日成绩、昨日节奏三种分享；节奏图保留峰值时段、24 小时曲线、活跃小时和节奏标签。
- 显示工具占比、连续活跃、费用估算说明和 TokenFleet 标识。
- 生成失败时给出具体阶段：渲染／编码／复制／保存，不只显示笼统错误。

## 8. 管理后台补发设备码

- 成员列表与成员详情提供“补发设备码”。
- 生成前明确展示：成员昵称、当前设备数、60 分钟、不新增成员、不占批次名额、原码不可找回。
- 已绑定成员的相同位置改称“添加新设备”，避免误把补发和多设备混为一谈。
- 原码只显示一次；关闭后不可恢复。补发在同一事务内让该成员旧的未使用有效码立即失效，只保留一个有效未用码；已使用码和审计记录不改变。

## 9. 必测状态

- 单屏／双屏；刘海／无刘海；菜单栏宽松／拥挤。
- 社群已连接／未连接／凭据失效／同步中／同步失败。
- 今日零使用／小额费用／未知价格／超过每日目标。
- 分享复制成功／保存成功／权限失败／编码失败。
- 无更新／可更新／下载中／签名不匹配／回滚。
- Apple Silicon／Intel；中文／英文；浅色／深色；窄窗口／标准窗口。
- 9 套主题逐一检查正文对比度、工具色可分辨性、选中态、成功／警告／错误语义和分享图输出。
- 价格测试覆盖精确模型、别名、价格版本、输入／输出／缓存读／缓存写、只有总量、未知模型和部分覆盖。

## 10. 明确不做

- 不改成全黑深海或科幻驾驶舱。
- 不删除“每天一个亿”。
- 不把现有用户熟悉的三页导航全部重排。
- 不把 Token 当绩效评分。
- 不为 Kimi、Cursor、DeepSeek 或 Gemini 伪造本地支持。
